# Black Myth: Wukong Benchmark Automation

Консольный инструмент на C# (.NET 10), который сам прогоняет **Black Myth: Wukong Benchmark Tool** из Steam два раза: CPU-тест и GPU-тест. Затем он собирает результаты в отчёт.

Отчёт содержит:

- характеристики компьютера: CPU, GPU, видеопамять, драйвер, RAM, материнская плата, монитор, ОС;
- результаты CPU- и GPU-теста из самого Benchmark Tool: средний, максимальный и минимальный FPS, 5-й перцентиль, 1% low, время кадра, загрузку GPU и видеопамять;
- настройки обоих проходов, подтверждение из файла результата, что игра их действительно применила, и обоснование выбора.

## Быстрый старт

Требования: Windows 10/11, [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0), Steam с установленным **Black Myth: Wukong Benchmark Tool** (бесплатный, App ID 3132990).

1. Один раз запустить Benchmark Tool вручную: принять соглашение, дождаться главного меню и закрыть. Без этого игра не создаёт файл настроек.
2. Собрать и запустить:
   ```powershell
   git clone <url-репозитория>
   cd VKTestBMWBenchmark
   dotnet run -c Release --project VKTestBMWBenchmark
   ```
3. На время тестов (≈ 8–10 минут) **не трогать мышь и клавиатуру**: инструмент сам нажимает кнопки в меню бенчмарка.

Отчёт выводится в консоль и сохраняется в `VKTestBMWBenchmark\bin\Release\net10.0-windows\Results\<дата_время>\`:

- `report.md` — отчёт;
- `cpu_raw.json`, `gpu_raw.json` — исходные файлы результатов Benchmark Tool.

Параметры командной строки:

| Параметр | Что делает |
|---|---|
| `--only cpu` / `--only gpu` | выполнить только один проход |
| `--no-pause` | не ждать Enter в конце (для запуска из скриптов) |

## Как это работает

Весь сценарий выполняется без участия человека:

```
поиск Steam → поиск Benchmark Tool → бэкап настроек
  → [настройки CPU → запуск → ожидание результата → закрытие]
  → [настройки GPU → запуск → ожидание результата → закрытие]
  → восстановление настроек → отчёт
```

**Поиск игры.** Путь к Steam берётся из реестра (`HKCU\Software\Valve\Steam`). Библиотеки читаются из `steamapps\libraryfolders.vdf`, папка игры — из `appmanifest_3132990.acf`. Поэтому инструмент работает, даже если игра стоит на другом диске.

**Изменение настроек.** Benchmark Tool хранит настройки в `b1\Saved\Config\Windows\GameUserSettings.ini`, в папке игры. Главное в нём — строка `UISettingData=(("Key", "Value"), ...)`: это значения из меню игры. Инструмент меняет только нужные ключи в этой строке и в секции `[ScalabilityGroups]`, остальной файл не трогает. Значения ключей проверены по меню игры и по файлу результата:

| Ключ | Значения |
|---|---|
| `QualityLevel`, `ShadowQuality`, … | 1 = Низкое … 5 = Кинематографичное |
| `ImageQuality` | высота рендера в пикселях; масштаб = ImageQuality / высота окна |
| `Rtx` / `RtxLevel` | полная трассировка вкл./выкл. / 1 = «Низк.» … 3 = «Ультра» |
| `InsertFrame` | генерация кадров: 1 = вкл., 0 = выкл. |
| `ScreenMode` + `FullscreenMode` | 1 = окно без рамок, 2 = окно |

Перед тестами исходный файл копируется в `%LOCALAPPDATA%\VKTestBMWBenchmark\Backup`. После тестов он возвращается на место, даже если запуск упал с ошибкой. Если прошлый запуск прервали, оригинал восстанавливается при следующем старте.

**Запуск теста.** Режима командной строки у Benchmark Tool нет. Поэтому инструмент запускает `b1_benchmark.exe` и повторяет цикл, пока не появится результат:

1. Enter — пропустить заставку «Нажмите любую кнопку»;
2. клик по пункту «Тест быстродействия» — координаты задаются в долях клиентской области окна, поэтому не зависят от разрешения;
3. Enter — нажать «Подтвердить».

Во время самого теста Enter и левый клик игра игнорирует (выход — правой кнопкой мыши), так что повторять цикл безопасно и распознавать экран не нужно. Чтобы забрать фокус у фонового процесса, перед `SetForegroundWindow` эмулируется нажатие Alt.

**Получение результатов.** По окончании теста бенчмарк пишет JSON в `%TEMP%\b1\BenchMarkHistory\Tool\<unix-время>`. Появление нового файла — сигнал завершения. После этого процесс игры закрывается принудительно, чтобы при штатном выходе она не перезаписала ini. В JSON есть итоговые метрики (`FPSAvg`, `FPSMin`, `FPS95`, …), настройки, с которыми прошёл тест, и покадровые записи (`Records`, ≈ 8–18 тыс. кадров). Из записей дополнительно считаются 1% low FPS, среднее время кадра и доля CPU в нём.

## Выбор настроек

### CPU-тест: окно 1280×720, рендер 25% (320×180), всё «Низкое»

Цель — чтобы видеокарта почти не влияла на результат. Тогда FPS определяется процессором: логикой, анимацией, физикой и подготовкой кадра.

- **Масштаб рендера 25%** — минимум, который принимает бенчмарк. Основная работа GPU (освещение, тени, пиксельные шейдеры) пропорциональна числу пикселей, а их в 16 раз меньше, чем при 100%.
- **Окно 1280×720 вместо полного экрана.** Пост-обработка, апскейлер и интерфейс считаются в *выходном* разрешении, а не во внутреннем. При 25% от 2560×1440 видеокарта всё равно была загружена на 93%. В окне 720p загрузка упала до 82%.
- **Все пресеты «Низкое», трассировка и размытие выключены** — убирают остальную нагрузку на GPU.
- **Генерация кадров выключена.** Сгенерированные кадры создаёт GPU без участия CPU, они завысили бы результат.
- **VSync и лимит FPS сняты**, чтобы ничего не ограничивало FPS сверху.

Проверка, что тест упирается именно в CPU: при уменьшении работы GPU в разы (выход 2560×1440 → 1280×720) средний FPS почти не изменился (127 → 125). Время работы CPU составляет ~85% от полного времени кадра.

### GPU-тест: родное разрешение, 100%, «Кинематографичное» + полная трассировка «Ультра»

Цель — максимальная нагрузка на видеокарту.

- **Родное разрешение монитора и масштаб 100%** — без апскейла, максимум пикселей.
- **Все пресеты «Кинематографичное»** — максимальные тени, GI, отражения, растительность.
- **Полная трассировка лучей (path tracing) на уровне «Ультра»** — самая тяжёлая для GPU часть игры, нагружает и RT-ядра.
- **Размытие в движении включено** — ещё один пост-эффект.
- **Генерация кадров выключена.** Иначе FPS отражал бы интерполированные кадры, а не реальную скорость рендера.

Проверка: загрузка GPU 92–97%, а работа CPU занимает лишь ~41% времени кадра. Значит, процессор большую часть кадра ждёт видеокарту.

## Пример результата

Intel Core i5-14400, GeForce RTX 3060 Ti 8 ГБ, 16 ГБ DDR4-2400, монитор 2560×1440:

| Метрика | CPU-тест | GPU-тест |
|---|---:|---:|
| Средний FPS | 126 | 52 |
| Минимальный FPS | 57 | 21 |
| 5-й перцентиль FPS | 113 | 43 |
| 1% low FPS | 101 | 40 |
| Время кадра, мс | 7,94 | 19,43 |
| Доля CPU в кадре, % | 85 | 41 |
| Загрузка GPU, % | 83 | 92 |
| Видеопамять (пик), ГБ | 5,3 | 6,4 |
| Узкое место | CPU | GPU |

## Структура проекта

```
VKTestBMWBenchmark/
├── Program.cs                     сценарий: два прохода, восстановление настроек, отчёт
├── Models/
│   ├── BenchmarkInstallation.cs   пути к Steam и игре
│   ├── BenchmarkProfile.cs        набор настроек одного прохода
│   ├── BenchmarkResult.cs         модель JSON-результата + производные метрики
│   └── SystemInfo.cs              характеристики ПК
└── Services/
    ├── SteamLocator.cs            поиск Steam, библиотек и Benchmark Tool
    ├── BenchmarkProfiles.cs       профили CPU/GPU-теста и их обоснование
    ├── BenchmarkConfigService.cs  бэкап, изменение и восстановление GameUserSettings.ini
    ├── BenchmarkRunner.cs         запуск, нажатия в меню, ожидание результата
    ├── NativeInput.cs             WinAPI: фокус окна, клавиатура, мышь
    ├── SystemInfoService.cs       WMI и реестр: CPU, GPU, RAM, плата, монитор
    └── ReportWriter.cs            вывод в консоль и report.md
```

## Ограничения

- Нажатия в меню эмулируются, поэтому во время теста нельзя пользоваться мышью и клавиатурой. Окно игры должно быть на основном мониторе.
- Пункт «Тест быстродействия» ищется по координатам меню. Если разработчики изменят меню бенчмарка, координату придётся поправить (`BenchmarkRunner.MenuBenchmarkX/Y`).
- Полная трассировка лучей в бенчмарке доступна только на видеокартах с аппаратным RT. На других картах игра сама отключит её, и это будет видно в строке «Подтверждение» отчёта.
